# live-recorder 容器启动报错修复报告

**日期**：2026-09-01
**项目**：`/Users/sec-t/Downloads/直播录制/live-recorder`
**问题**：QNAP Container Station 中容器启动即崩溃，`ModuleNotFoundError: No module named 'gmssl'`

---

## 一、根因分析

`requirements.lock`（pip-compile 生成）**漏掉了 `gmssl` 依赖**，但代码在模块顶层直接导入：

```
app/main.py → app/routers/__init__.py → rooms.py → services/platform/__init__.py
→ douyin.py → vendor/abogus.py → from gmssl import sm3, func  ← 崩溃点
```

**为什么构建时不报错**：lock 中不含 gmssl，pip 正常构建完成；容器启动时才触发导入链崩溃。属于典型的「依赖清单不同步」。

---

## 二、修复清单

| # | 文件 | 改动 |
|---|------|------|
| 1 | `requirements.lock` | 补 `gmssl==3.2.2`（含传递依赖 `pycryptodomex==3.23.0`） |
| 2 | `requirements.txt` | 补 `gmssl==3.2.2`（直接依赖显式声明） |
| 3 | `app/services/platform/vendor/abogus.py` | gmssl 改为**软依赖**：`try/except ImportError` + `GMSSL_AVAILABLE` 标志。缺失时模块仍可导入，仅抖音作品订阅的 a_bogus 签名不可用；调用签名时抛出带修复指引的明确 `RuntimeError`。**核心直播录制功能不再受此依赖影响** |
| 4 | `app/routers/__init__.py` | `__all__` 补 `works`（`main.py` 已导入但包导出遗漏） |
| 5 | `scripts/check_deps.py`（新增） | 构建期校验 `requirements.txt` 全部直接依赖可导入，把「运行时崩溃」提前为「构建失败」 |
| 6 | `Dockerfile` | 依赖安装改为「lock + txt 两遍安装 + check_deps 校验」；**修复 COPY 路径 bug**（原 `COPY requirements.txt ... ./scripts/` 会把依赖文件复制进子目录导致 `-r requirements.txt` 找不到文件，已改为 `COPY requirements.txt requirements.lock* ./`） |

## 四、QNAP 部署步骤

```bash
# 1. 将修复后的代码同步到 QNAP（git pull 或拷贝项目目录）

# 2. 重建镜像（QNAP Container Station 或 SSH 进 NAS 执行）
cd live-recorder
docker compose build

# 3. 重启容器
docker compose up -d

# 4. 验证
docker compose ps                    # STATUS 应为 running (healthy)
curl -f http://localhost:8000/api/health
```

> 镜像源已默认配置阿里云加速（docker-compose.yml 内 `APT_MIRROR=mirrors.aliyun.com`、`PIP_INDEX=https://mirrors.aliyun.com/pypi/simple/`）。

## 五、后续建议

1. **依赖同步机制**：`requirements.lock` 每次依赖变更后需重新 `pip-compile`，建议加入 CI 检查（比对 lock 与 txt 差异）
2. **健壮性**：abogus 软依赖降级已生效，即使未来再次出现依赖漏装，应用核心功能（直播录制、房间管理、回放管理）不受影响
3. 本地开发环境（macOS）无 Docker daemon，未能实测镜像构建；构建已在依赖层面完整验证，若 QNAP 构建仍有异常请提供日志
